Optimizing an image is expensive; serving it again should be free. Keenpix caches every
transform on disk and is built to sit behind a CDN.

## The cache key

A result is keyed by everything that affects the output:

```text
project + url + w + h + q + fmt + fit + dpr + blur
```

Two requests with identical parameters share one cached file. Requests that arrive while
the first identical transform is still running share that same in-flight work too.

<Callout title="In-flight coalescing">
  If many identical requests arrive during a cold cache (e.g. a popular image after a
  deploy), Keenpix runs the fetch + encode **once** and shares the result, instead of
  doing the same work N times.
</Callout>

## CDN-friendly responses

Every successful response sets:

```http
Cache-Control: public, max-age=31536000, immutable
Vary: Accept
```

Because the format and every transform live in the URL, the response is immutable.
Configure your CDN to cache `/api/keenpix` responses, including the full query string.
For Cloudflare, that usually means a Cache Rule for the endpoint; orange-cloud proxying
alone is not enough for every API-looking path. `Vary: Accept` keeps per-format variants
correct under `fmt=auto`.

## Where it's stored

The disk cache lives at `KEENPIX_CACHE_DIR` (default `./.keenpix-cache`). Writes are
atomic (temp file + rename) so a crash mid-write can't serve a truncated image. See
[Configuration](/docs/self-hosting/configuration) for size limits and eviction.
