# Keenpix Cloud v0.2.0 release notes

Release date: 2026-07-13
Branch: `cloud`
Target: `cloud` → `master`; do not merge without explicit owner approval.

## What ships

- Managed cloud authentication, organizations, organization-owned projects and API keys, Google sign-in, Postmark transactional email, Polar subscriptions, usage controls, and operator workflows.
- Consent-aware acquisition-to-activation analytics through a dedicated Keenpix GA4 property, with sampled first-party LCP, INP, and CLS events. A dedicated Keenpix GTM container remains available as a fallback.
- Canonical apex routing, strict TLS, metadata/schema/sitemap corrections, Windows-compatible SEO drift checks, narrow-mobile navigation fixes, and response security headers.
- Public About, security, status, support, author, methodology, pricing, comparison, changelog, self-hosting, and `security.txt` surfaces.
- Ten sourced blog articles with visible author ownership and article-specific social imagery. The JoodCMS code-backed case study also ships with a generated 1600×900 WebP cover and 1200×630 JPEG Open Graph asset.
- Three monthly Polar products: Basic ($9), Pro ($19), and Business ($29), each with the documented included bandwidth and metered overage behavior.

## Cloud provider configuration

- Google OAuth uses `https://keenpix.com` as its authorized origin and `https://keenpix.com/api/auth/callback/google` as its production redirect URI. End-to-end sign-in reached the authenticated dashboard.
- Google Analytics is isolated in the dedicated `Keenpix` account and `Keenpix Cloud` property (`G-C04VQED7GV`). GTM is isolated in the dedicated `Keenpix` account and `keenpix.com` container (`GTM-TFJ9TQDN`).
- Search Console owns the `keenpix.com` domain property and has a submitted sitemap. The live sitemap now contains 60 URLs; the last provider report still showed 57 discovered URLs while reprocessing catches up.
- Polar production and sandbox callbacks use apex paths only:
  - `https://keenpix.com/api/auth/polar/webhooks`
  - `https://keenpix.com/api/auth/polar/sandbox-webhooks`
- Postmark uses the `raed` server, verified `keenpix.com` sending domain, `Keenpix <no-reply@keenpix.com>` sender, and `outbound` stream.
- Cloudflare performs one-hop 308 canonical redirects to HTTPS apex, uses Full (Strict) TLS with TLS 1.2 minimum, bypasses edge caching for `/app/*` and `/api/*`, applies baseline security headers including to 404 responses, and publishes DMARC aggregate reporting to `fariq@keenpix.com`.
- Coolify runs only the cloud application `keenpix-branch-cloud`. The final runtime is commit `2779d60`, deployment `k960s5uqueopks3bftqzt023`.

No credentials, provider tokens, webhook secrets, or raw credential files are stored in Git.

## Honest limitations

- Google’s automated scanner paused the native GTM Google tag. Production therefore uses the consent-gated direct GA4 path as the primary collector; no traffic, funnel conversion, Search Console growth, or field Web Vitals result is claimed before data accumulates.
- Search Console has not yet reprocessed the live 60-URL sitemap; its last confirmed provider count was 57 discovered URLs.
- The authenticated cloud organization has no paid production subscription. Project creation is correctly plan-gated, so a live project/API-key mutation was not fabricated or unlocked by starting a charge. Relational organization/project/API-key isolation is covered by integration tests.
- No customers, reviews, ratings, certifications, SLAs, universal savings, or unsupported competitor claims are invented.
- Migration and cutover are not part of this release. Legacy production was not accessed, queried, changed, restarted, redeployed, migrated, or used for testing.

## Rollback

1. Roll back only `keenpix-branch-cloud` to the previously verified cloud image in Coolify.
2. Keep Cloudflare routing on the cloud environment; do not route to or operate legacy production.
3. Disable Google OAuth or analytics public identifiers if either integration causes an authentication or consent regression.
4. Preserve Polar and Postmark provider records for diagnosis.
5. Re-run health, auth, canonical, transform, dashboard, and provider smoke checks on the rolled-back cloud revision.
