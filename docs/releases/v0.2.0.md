# Keenpix Cloud v0.2.0 release notes

Release date: 2026-07-11
Branch: `cloud`
Target: `cloud` → `master` pull request; do not merge without explicit owner approval.

## What ships

- Managed cloud authentication, organizations, Google sign-in support, Postmark transactional email, Polar subscriptions/usage, spending caps, and admin operations.
- Consent-aware acquisition-to-activation analytics, GA4/GTM integration hooks, and sampled first-party LCP/INP/CLS events.
- Canonical apex routing, Strict TLS, metadata/schema/sitemap corrections, cross-platform SEO drift checks, and mobile public-navigation fixes.
- Public About, security, status, support, author, methodology, pricing, comparison, changelog, and self-hosting decision surfaces.
- Nine blog articles with primary-source disclosures and a required, versioned Takumi hero/OG pipeline shared by visible images, social metadata, and BlogPosting schema.
- Hardened Polar usage idempotency and organization billing-portal recovery; PII-safe Postmark error handling.

## Cloud configuration

The release expects secrets in the cloud deployment store, never in Git:

- application/auth: `KEENPIX_MODE=cloud`, apex application/auth URLs, strong auth secret;
- Google: server-only OAuth client ID/secret and public GTM container ID;
- Polar: production organization token, production server selection, webhook signing secret, and all required subscription events;
- Postmark: `EMAIL_PROVIDER=postmark`, server token, verified `Keenpix <no-reply@keenpix.com>` sender, and `outbound` stream;
- storage/analytics/jobs: Postgres, ClickHouse, shared object cache, Cloudflare analytics token/zone, and cron secret.

## Verification evidence

- Local code gate: lint, typecheck, unit/integration tests, dependency/dead-code review, and production build are required before push.
- Cloudflare: apex HTTPS direct; apex HTTP and both `www` schemes preserve path/query and redirect once with 308; Full (Strict), TLS 1.2 minimum.
- Search: canonical/robots/sitemap/schema/OG and SEO drift baseline/compare are required after the release deploy.
- Browser: 320, 360, 375, 390, 412, tablet, and desktop public layouts plus unauthenticated/authenticated product flows are required after deploy.
- Integrations: OAuth, consent, GTM/GA4 events, Polar webhook/portal/usage, Postmark delivery, health, scheduled jobs, and cloud logs require deployed evidence.

The detailed evidence and unresolved gates live in `V0.2.0-RELEASE-TRACKER.md` and the pull request. A passing code build is not presented as proof that provider data has accumulated.

## Known limitations at release preparation

- GA4, Search Console, and real-user Web Vitals need live traffic before meaningful baselines or conversion rates exist.
- Google OAuth is implemented but disabled until the owner creates a fresh client and enters its secret directly in the cloud secret store. No generated client credentials remain active.
- The GTM container exists, but its authenticated tag-template picker returned no tag types; it remains unpublished and analytics collection is not claimed.
- No customer reviews, ratings, certifications, uptime percentage, SLA, or benchmark results are claimed.
- Postmark delivery remains blocked until an authorized non-suppressed test inbox is available; provider/domain configuration alone is not delivery proof.
- Polar sandbox webhook E2E requires an isolated cloud staging callback. Sandbox events must not target the production application.
- Legacy data migration and API-host cutover are excluded from v0.2.0 release execution and require a later explicit instruction.

## Rollback

1. Revert the cloud application to the previously verified cloud commit/image in Coolify.
2. Keep Cloudflare apex routing on the cloud application; do not route to or restart legacy production as part of this release rollback.
3. Disable the new public GTM container ID and Google OAuth availability if either integration causes auth or privacy regressions.
4. Preserve Polar/Postmark webhook and provider logs for diagnosis; do not delete billing/email records.
5. Re-run health, auth, canonical, transform, and dashboard smoke checks against the rolled-back cloud release.
