# Keenpix Cloud v0.2.0

## Summary

This PR promotes the `cloud` branch as Keenpix Cloud v0.2.0. It is cloud-only: legacy production, its service, and its database were not accessed, queried, changed, restarted, redeployed, migrated, or used for testing. Do not merge without explicit owner approval.

## Release scope

- Managed cloud auth, organizations, plan-gated projects, relational organization/project API-key scoping, billing, usage controls, and transactional email.
- Production Google OAuth with apex origin/callback and verified dashboard sign-in.
- Dedicated Keenpix GA4 and GTM accounts, consent-aware acquisition-to-activation events, and Cloudflare Web Analytics RUM for LCP/INP/CLS and page performance.
- Apex/HTTPS canonical routing, truthful metadata/schema/sitemap dates, `security.txt`, security headers, SEO drift, and narrow-mobile fixes.
- Trust, pricing, methodology, comparison, author, support, and self-hosting surfaces.
- Ten sourced blog posts with article-specific social imagery, including a disclosed, code-backed JoodCMS integration case study with generated cover/OG artwork.
- Polar production/sandbox wiring on apex paths only, Postmark delivery, release docs, rollback notes, and a deferred migration-readiness package.

## Known limitations

- Google’s scanner paused the native GTM Google tag. Search Console reports no security issue, and triggerless GTM version 4 was published for the supported automated rescan. Consent-gated direct GA4 remains primary until Google clears it. No conversion-rate, GSC-growth, or field-performance result is claimed.
- The live sitemap contains 60 URLs; GSC’s last processed count remains 57 pending recrawl.
- No production billing trial was started merely to manufacture live project/API-key mutation evidence.
- Migration/cutover and all legacy access remain deferred to a later explicit owner instruction.

## Rollback

1. Roll back only the cloud application to the previously verified cloud image.
2. Keep routing on cloud; do not route to, restart, query, or use legacy production.
3. Disable direct GA4/GTM or Google OAuth if an integration causes a privacy/auth regression.
4. Preserve Polar and Postmark records, then rerun cloud health, auth, transform, canonical, and dashboard smoke checks.
