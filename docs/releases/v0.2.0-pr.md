# Keenpix Cloud v0.2.0

## Summary

This release promotes the `cloud` branch as Keenpix Cloud v0.2.0. It adds the managed-cloud product surfaces and hardens the public site, SEO, analytics, authentication, billing, email, and deployment paths for production use.

This pull request is cloud-only. Legacy production, its service, and its database were not accessed, queried, changed, restarted, redeployed, migrated, or used for testing. The pull request must not be merged without explicit owner approval.

## What ships

- Managed cloud authentication, organizations, billing, usage controls, operations, and transactional-email integration.
- Consent-aware GTM/GA4 funnel hooks plus sampled first-party LCP, INP, and CLS reporting.
- Apex canonical routing support, corrected metadata and structured data, truthful sitemap dates, and Windows-compatible SEO drift checks.
- Narrow-mobile navigation and touch-target fixes, tighter font discovery, and reduced public-page payload.
- About, security, status, support, author, methodology, pricing, comparison, changelog, and self-hosting trust surfaces.
- Nine sourced blog articles and required article-specific Takumi hero/Open Graph assets.
- Polar usage idempotency, billing-portal recovery, webhook verification, and Postmark error handling that avoids recipient disclosure.
- Version, changelog, deployment guidance, release notes, rollback notes, and the live evidence tracker for v0.2.0.

## External blockers and known limitations

- Google OAuth remains disabled. The initially created clients were deleted when secure secret transfer was not possible. The owner must create a fresh production client and enter its secret directly into the cloud secret store.
- Search Console's first sitemap submission initially displayed “Couldn't fetch”; ownership and submission are complete, but provider processing must be rechecked after propagation.
- GTM remains unpublished because its authenticated tag picker exposed no selectable tag types. No GA4 collection or accumulated conversion data is claimed.
- Postmark rejected the low-risk cloud-only delivery test with provider code 406 because the authorized recipient is inactive/suppressed. Delivery proof requires an authorized, non-suppressed recipient.
- Polar sandbox checkout/webhook E2E requires a cloud-owned isolated callback. Sandbox events were not pointed at production. Production benefit attachment still requires `pnpm billing:configure-benefits -- --server=production --apply` with the runtime token; Coolify's web terminal did not establish an interactive shell, so no apply was attempted.
- Optional Cloudflare analytics variables are unset, so the application correctly reports that edge/origin metric splitting is not configured.
- Meaningful GA4, Search Console, and real-user Web Vitals baselines require accumulated live traffic.
- No customer reviews, ratings, certifications, SLAs, benchmarks, or unsupported competitor claims were invented.
