Use `@keenpix/nuxt` as a custom provider for `@nuxt/image`. Nuxt generates
responsive candidates; Keenpix delivers each transformed image.

<Callout title="Published 0.3.2 installation caveat">
  The 0.3.2 npm tarballs currently contain unresolved `workspace:^` dependencies.
  A normal npm installation fails with `EUNSUPPORTEDPROTOCOL`. The provider setup
  below requires those package dependencies to be resolved; check for a corrected
  publication before adopting it.
</Callout>

## 1. Install

From an existing Nuxt application, add the Nuxt Image module and the Keenpix package:

```bash
pnpm exec nuxt module add image
pnpm add @keenpix/nuxt
```

The module command installs `@nuxt/image` and registers it. The setup below uses
Nuxt Image v2 and Nuxt 4.

## 2. Create the provider

```ts
// providers/keenpix.ts
import { defineProvider } from '@nuxt/image/runtime'
import { createManagedKeenpixConfig, createNuxtImageProvider } from '@keenpix/nuxt'

const managed = createManagedKeenpixConfig('YOUR_PROJECT_ID')

export default defineProvider(
  createNuxtImageProvider({
    baseURL: managed.baseUrl,
    projectId: managed.projectId,
    projectInPath: managed.projectInPath,
  }),
)
```

`baseURL` in this package means the **delivery base**, such as
`https://cdn.keenpix.com`, never the source origin. `createManagedKeenpixConfig`
sets that delivery base and puts the project id in `/p/<project-id>`. The source
origin is part of each absolute `src` instead.

## 3. Register the provider

Keep a single `@nuxt/image` entry in your module list:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['@nuxt/image'],
  image: {
    provider: 'keenpix',
    providers: {
      keenpix: { provider: '~/providers/keenpix' },
    },
  },
})
```

In Nuxt 4, `~` resolves to `app/` by default: place the file at
`app/providers/keenpix.ts`. In Nuxt 3 it normally resolves to the project root,
so use `providers/keenpix.ts`. A custom `srcDir` changes that location.

## 4. Use NuxtImg

```vue
<!-- app/app.vue (Nuxt 4) -->
<template>
  <NuxtImg
    src="https://assets.example.com/hero.jpg"
    width="1200"
    height="800"
    quality="75"
    sizes="100vw md:50vw"
    alt="A mountain at sunrise"
  />
</template>
```

<Callout>
  Add `assets.example.com` to your Keenpix project's origin allowlist in
  **Settings > Security**. Sources must be absolute URLs on allowlisted hosts.
  `/hero.jpg` and `photos/hero.jpg` produce relative sources that managed delivery
  rejects with HTTP 400. The provider's `baseURL` does not resolve relative sources.
</Callout>

## Nuxt Image v1

The published package supports the v1 provider contract too. Replace only the
provider file with a named `getImage` export; v1 does not use `defineProvider`:

```ts
// providers/keenpix.ts
import { createManagedKeenpixConfig, createNuxtImageProvider } from '@keenpix/nuxt'

const managed = createManagedKeenpixConfig('YOUR_PROJECT_ID')

export const { getImage } = createNuxtImageProvider({
  baseURL: managed.baseUrl,
  projectId: managed.projectId,
  projectInPath: managed.projectInPath,
})
```

See the official [Nuxt Image v2 migration guide](https://image.nuxt.com/get-started/migration)
for the provider export change.

## Formats and responsive delivery

The `format` prop maps to Keenpix's `fmt` query parameter. Leaving it unset lets
Keenpix negotiate output using the browser's `Accept` header. Set `format="webp"`
or `format="avif"` only when you want a fixed output format. To return an SVG
source as optimized SVG, request `format="svg"`.

Use `sizes` to describe the image's actual layout slot. Inspect the rendered
`srcset` for managed URLs with different widths, then resize the viewport and
check the selected candidate. Confirm the delivery cache separates negotiated
formats and test a rejected source host before launch.

For self-hosting, pass your own delivery `baseURL` and public `projectId` to
`createNuxtImageProvider`, with `projectInPath: false`. Keep absolute sources;
this setting uses a project query parameter on your own image host.
