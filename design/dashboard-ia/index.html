Four spheres, one control plane

The current /app overloads a single sidebar with a scope toggle: Dashboard, Analytics, Logs and Settings each mean two different things depending on whether you've picked a project. These three prototypes each give the four concerns a real home. Same data, different navigation — that's the decision.

THE MODEL
1
Fleet — bird's-eye
Aggregate KPIs + a project comparison table across every project.
2
Project — drill-down
One project's overview, analytics and live logs.
3
Instance / product
Operations, API keys, staff, email, and instance-wide pipeline defaults.
4
Project settings
Origin, pipeline defaults, and the host allowlist for that project.
THREE APPROACHES
Lowest-risk alternative B · Grouped single sidebar Lowest-risk evolution — three labelled groups, nothing hidden. Open
  • No modes — fleet, project and instance each get a group.
  • Closest to today's code; cheapest to ship.
  • Surfaces the hidden Workspace tabs as a first-class Instance group.
  • Denser sidebar.
  • "Current project" is a persistent global, not a place you enter.
Target long-term A · Drill-down workspace Vercel/Linear-style — the sidebar follows you into a project. Open
  • Cleanest scope separation — never unsure where you are.
  • "Settings" only ever means project settings.
  • Scales best with many projects.
  • A mode switch to learn.
  • Two clicks to hop between two projects.
Selected direction C · Command center Top tabs + a top-bar scope selector that moves between all projects and one — the data tabs follow. Open
  • One top-bar scope selector unifies all-projects and per-project.
  • Overview reframes in place; Analytics & Logs follow the scope.
  • Logs swaps Project ↔ Domain column and filters rows by scope.
  • Settings hub splits project vs instance on one screen.
  • Biggest departure from today's sidebar.
  • Top-tabs scale worse than a sidebar as sections grow.
